# 手机定位与高德核对（2026-09-19）

入口不变：https://<你的域名>/fzu/ 。在“本人核对的签到位置”中使用两个按钮。

## 使用

1. 在iPhone Safari中打开并登录管理页，点击“手机获取当前位置”，由本人决定是否授权网站定位。
2. 按浏览器Geolocation标准，将返回的WGS-84在手机浏览器内换算为GCJ-02，仅填入当前草稿；显示设备精度估计和北京时间采样时间。
3. 点击“打开高德核对”。确认提示后，新页面显示当前草稿点位；请本人核对真实所在位置，填写/核对地址并重新勾选位置确认。
4. 需要保留时再点击“保存配置并暂停”；先只读预检，条件满足且本人授权后再恢复定时。定位和看地图都不会自动保存或提交签到。

精度超过100米会明显警告。显示的精度是设备估计，**不包含换算误差，也不是保证**；位置不准时不要直接确认，可改善定位条件再试，或手工填写本人核对的GCJ-02坐标。手工GCJ-02不会再次转换。
未授权、定位失败、12秒定位超时或15秒页面等待上限都不会改写原有坐标；可以取消。保存/退出/手工改位置后，迟到的回调不会覆盖草稿。
地址不会自动拼宿舍楼或猜测；即使手机刚定位，之后服务器签到仍使用保存的固定坐标，不能证明本人每晚实时在校。离校、请假仍须暂停或设置跳过日期。

## 高德链接与隐私

不用安装地图SDK、不需要提供API Key，没有内嵌第三方地图、自动反查地址或后台地图请求。
仅在点击并确认后，发送当前草稿经纬度和固定标题“待核对的位置”，不发送学校账号、密码、Token或填写的真实地址。
链接明确`coordinate=gaode`（GCJ-02）和`callnative=0`（浏览器模式），使用`noopener,noreferrer`隔离新页面。
当两项坐标均为空时打开高德官方拾取器，不发送坐标。当前高德说明游客/未认证开发者只显示两位小数，不能据此确认具体楼栋；足够精度的拾取可能需要高德登录或认证。

官方依据：https://lbs.amap.com/api/uri-api/guide/mobile-web/point 。只用公开示例核对过跳转，未把用户真实坐标发送给地图服务。

## 权限与部署边界

- 只给`/fzu/`、`/fzu/index.html`文档开放`geolocation=(self)`；摄像头、麦克风继续禁止。
- `/fzu/api/*`与静态脚本本身仍返回`geolocation=()`；该站点原页面继续禁用定位。没有全站或通配符授权。
- 认证、CSRF、CSP及no-store保护保留；登录前页面不主动调用定位，登录后也只有明确点击才调用。
- 新纯前端模块：`admin_static/location.js`；静态白名单只新增该明确文件。更新管理页服务使权限头生效，可能需要重新登录，已保存学校凭据不变。
- 服务器没有读取手机GPS的后台能力。真实iPhone授权/定位是否准确需要本人在手机上确认，不能用浏览器mock当实机GPS证据。
