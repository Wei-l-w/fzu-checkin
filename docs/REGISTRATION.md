# 注册与审批

## 页面操作

1. 管理员登录，在「成员管理」展开「注册与审批」，点击「开放注册」并确认。
2. 点击「复制注册链接」，发给希望加入的成员。链接只是入口，不是邀请码，也不会绕过审批。
3. 申请人填写用户名、至少 10 个字符的密码和可选申请说明。不要填写学校密码、Token 或位置等签到信息。
4. 管理员在申请列表选择「通过」或「拒绝」。拒绝时可填写原因。
5. 申请人可在登录页「查询审核」输入申请时的用户名和密码查询结果。获批后用同一组凭据登录；完成自己的签到配置、位置确认和只读预检后，才能手动恢复定时。

公开注册默认关闭。关闭注册只拒绝新申请，不影响现有成员、待审批申请或结果查询。审批列表默认折叠，展开后限高滚动；收起时每 30 秒更新待审批数量，也可以手动刷新。
未审批或被拒绝的申请不是正式账户，不能取得登录会话、读取签到配置或调用控制接口。

## 数据与权限

- 不修改现有账户格式，申请另存于账户文件同目录的 `registrations.json`，目录 0700、文件 0600。
- 申请密码只保存固定参数的 scrypt 盐值与散列，不存明文；管理员 API 不返回散列或密码，页面和日志不回显凭据。
- 查询审核需验证申请密码，不创建登录会话。申请说明和拒绝原因仅作纯文本显示。
- 只有 owner 可读申请列表、开关注册、通过或拒绝；写操作仍要求同源 JSON 和当前会话的 CSRF 校验。
- 申请角色固定为 member，不能自行传入角色、已批准状态、其他档案名或学校配置。
- 开户前创建空白、禁用且有暂停标记的独立档案。审批本身不会创建/启用 timer，不调用学校或通知服务。
- 并发写入使用进程锁和文件锁；审批通过幂等。资料目录存在但不属于本次申请时拒绝覆盖。

## 防刷及容量

全站每 10 分钟最多 10 次有效格式的申请尝试、30 次结果查询尝试；错误凭据和重复申请也计数。两种额度相互独立，且不占用管理员正常登录的限额。不信任来访者自行设置的转发 IP 请求头。
计数持久化，重启不能重置限流；繁忙时返回 429 和 `Retry-After`。注册的密码散列计算与登录共用有限的并发槽。

最多保留 64 个待审批/处理中申请、256 条总申请记录，正式用户仍遵循原有 64 人上限。到达容量后拒绝新增，不自动删除已有申请或用户数据；需要管理员先在服务器私有目录备份并归档历史申请。对于少量同学使用，可在接收完申请后关闭入口。

## 中断与维护

审批先保存批准意图，再创建所属档案与账户，最后写完成记录。普通失败在页面提示；如果操作中断显示「批准处理中」，管理员可点「重试通过」。重试不会重置已经创建的配置，也不会通过旧申请重新启用已被移除的成员。
申请数据损坏、权限不安全、账户/档案冲突会阻止操作，不把申请自动放行。处理冲突前先备份私有数据，不能用覆盖整个账户文件的方式恢复。

关闭注册可立即停止接收新申请；若回滚代码，应恢复匹配版本的 Web 后端、认证模块和静态页面，不覆盖账户文件、注册申请文件或成员配置。已有正式成员保持原有数据，旧版只是没有注册和审批入口。
